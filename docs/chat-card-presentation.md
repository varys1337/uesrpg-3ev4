# Uniform opposed cards and compact actor dialogs

Weapon and spell checks now render their participant headers, context, TN and roll rows, outcomes, and target sections through `src/core/opposed/shared/card-rendering.js`. Both use the existing shared damage/healing panel. Their separate workflows continue preparing their own data, reveal conditions, target-number conventions, permissions, and actions.

The shared card content uses 14px primary and 12px secondary Foundry text tokens, 16px headings, 24px item icons, and compact gaps. The participant layout switches from stacked rows to paired panels at 26.25rem of card content width (420px at default text size). Enlarged text raises that threshold. Names, contexts, result labels, and action text wrap. Multiple-target cards render the attacker once, with each defender's existing action attributes and application payload retained.

Spell rows retain school, level, spell strength, cost/refund presentation, enchantment binding strength, automatic results, characteristic defenses, and block/ward information. No Defense keeps the spell workflow's `-` TN. Pending, applied, partial, and failed application displays continue using existing persisted state. A repeated single component source may use the Damage/Healing label when its value exactly matches the payload header; separate components retain their source names. Saved spell calculations appear in a collapsed **Detail** disclosure with their field names preserved, while final Damage/Healing remains visible.

Unopposed casting and healing use one item header and aligned context/result rows. Shock prompts use compact target/location rows and retain the existing unrolled and resolved states. Skill/characteristic opposed cards share the participant structure. Other existing system cards receive shared spacing and wrapping rules without a new renderer or workflow. Legacy opposed CSS selectors remain supported; stored chat messages are not rewritten.

Actor option dialogs retain native inputs and their submission names, defaults, eligibility checks, selection resets, and dependencies. Specialization, resistance, sensory, talent, and spell-option explanations use the existing system tooltip helper. Disabled options expose help through a focusable label; enabled inputs remain keyboard focusable. Dynamic skill and spell selections refresh help. Combat and casting choices use centred warm bars with visually hidden native glyphs and a visible bar focus outline. Ordinary skill toggles retain Foundry's visible glyphs. Required choices, validation messages, and application failures remain visible.

No schema, setting, migration, public API, synchronization, or damage-application changes are introduced. Settings retain their existing Foundry-native presentation. Legacy-item migration failures remain a separate task.
